# Generation Workflow｜图像生成工作流

目标：让生成模型清楚理解什么最重要、什么必须保持、什么可以自由发挥，而不是写最长的提示词。

```text
确认目标 → 确认尺寸 → 收集必要素材 → 判断角色阶段 → 必要时生成角色设定板 → 整理约束 → Concept Brief → 分配参考职责 → 生成指令 → 首轮生成 → 分层诊断 → 编辑或重生成 → 用途验证
```

## 生成准备度

直接生成：用户要求图像、母题明确、人物和必要限制已知、目标尺寸或比例已经确认一次、所有声明为必须沿用的素材已经提供；新增人物已完成一次风格引导，复用人物已有合格设定板或当前只是首张场景，且剩余不确定性只影响局部。用户明确授权 Pixel Adventure Director 决定尺寸时，先声明所选尺寸再执行。

先做概念：只有抽象主题；现实与概念世界存在根本分歧；多个隐喻竞争；人物是否出现会改变画面；用途显著改变构图；或用户明确要讨论。

暂不生成：尺寸尚未确认且用户未授权 Pixel Adventure Director 决定；缺少用户声明必须沿用的角色、品牌、UI、构图或风格素材；新增人物尚未完成一次风格引导；同一人物准备第二次进入新场景但尚无合格设定板；不可变要求冲突；不知道延续哪个角色；继续必然重大偏离。尺寸、风格和素材要求应在前置批量确认中提出，不要等出图后补问。

## Production Intake｜生产信息与素材

最终图像生成前完成一次生产检查：

1. **Target Canvas**：确认宽 × 高或比例，并说明该选项适配的载体位置；
2. **Safe Area**：确认标题、按钮、Logo、裁切或出血区域；
3. **Character Source & Stage**：新建角色、首张场景中的临时角色、第二次复用角色，还是已有正式设定板；新增时完成一次风格引导，沿用时提前索取清晰参考和 Hard Lock；
4. **Project Assets**：是否存在 Logo、品牌色、字体、UI 线框、构图参考、地点或指定物件；
5. **Reference Roles**：让用户上传真正必要的素材，并说明每张负责人物、风格、构图、环境或物件；
6. **Non-negotiables**：记录必须保持与必须避免的内容。

把这些内容并入第一轮方向确认；只有尺寸或素材要求必须依赖已选用途、人物来源或母题时，才放到第二轮。不得为每类素材开启独立追问。用户说明“没有固定素材”后不要继续索取；用户说明存在必须沿用的素材时，在收到前不要生成最终图。

目标画布与生成工具的原生输出尺寸可以不同。若工具不支持精确目标尺寸，先按目标比例和安全区构图，再通过裁切、扩展或后期适配交付；必须向用户说明，不得默默改变规格。
## Character Continuity Gate｜角色连续性门槛

生成含人物的画面前判断：

- **新增人物首次出场**：先完成一次人物风格引导，记录 Provisional Character Lock，然后可生成首张场景；
- **同一人物第二次进入新场景**：如果没有角色形象设定板，先使用首张人物图生成设定板和文字 Character Lock，暂不直接生成第二张场景；
- **已有合格设定板**：直接以设定板为最高优先级 Character Reference；
- **首张图的局部修改**：保持当前参考，不触发设定板门槛。

角色形象设定板应使用中性背景、稳定尺度和统一光线，包含至少三个可比对的全身视图、头像或发型细节、固定色板、服装层次与标志配件。不要加入场景、戏剧动作、透视夸张、强环境色或临时装备。

设定板生成后保存为后续场景的连续性资产，并记录 Hard Lock、Soft Lock、Free Variables 与 Identity Anchors。只有设定板通过身份一致性检查后，才继续第二张场景。若上一张人物图无法访问，引导用户重新上传；不得仅凭“沿用上一个角色”的文字描述重新创造一个近似人物。
## 约束优先级

1. 用户当前明确要求。
2. 参考图和 Character Lock。
3. 已确认用途、画幅与构图。
4. 场景母题和世界规则。
5. Pixel Adventure Director 视觉语言。
6. 可自由发挥的局部细节。

风格参考不能改变角色身份；冒险化不能破坏指定现实场景；环境丰富不能改变主焦点。

## Concept Brief

按任务选用实际有用字段：

```text
用途 / 目标尺寸或比例 / 安全区
核心状态 / 核心隐喻 / 场景母题
场景类型 / 世界模式 / 冒险强度 / 世界规则
人物 / 行动 / Character Lock
构图 / 主焦点 / 次焦点 / 安全区
像素密度 / 色彩 / 光线 / 气氛
必须保持 / 需要避免
```

不为填满模板补充无用设定。

## 生成指令结构

使用有层级的自然语言，而非关键词堆砌：

1. **结果与用途**：要生成什么、用于什么、画幅与留白。
2. **场景母题**：一到两句话描述核心画面，权重最高。
3. **空间构图**：镜头、主体位置、人物大小、景深、视觉路径和安全区。
4. **角色行动**：身份、Character Lock、动作及与环境的关系。
5. **世界规则**：异常如何触发、变化和被看见。
6. **视觉语言**：像素密度、形体、色彩、光线、空气和材质。
7. **约束与避免**：只写最可能发生且会破坏结果的偏差。

提示语言不强制英文。中文用于准确概念与语境，稳定美术术语可保留英文；不做逐句双语重复。同一概念只保留一种明确表述。

## 参考图职责

在生成前引导用户上传必要参考，并为每张参考图分配职责：

- **Character Design Sheet**：后续场景中的最高优先级身份基准，负责 Hard Lock、固定色板、服装结构、Identity Anchors 与稳定视图；
- **Character Reference**：首次提炼身份或生成设定板时使用，负责发型、比例、服装、主色和标志物；不复制无关背景和姿势。
- **Style Reference**：像素密度、色彩、形体、光影和材质；不覆盖 Character Lock。
- **Composition Reference**：镜头、主体位置、空间比例、路径和留白；不复制人物世界观。
- **Environment Reference**：建筑、地貌、材质、地理关系和时代感。
- **Object Reference**：只用于指定物件。

冲突时按职责解决，不平均混合成新角色。两张角色参考互相冲突且用户未指定基准时才询问。只使用真正有职责且最清晰、最接近目标的参考图。

## 首轮策略

- **Single Direction**：需求明确；验证母题、构图、角色和冒险强度。
- **Multiple Directions**：隐喻或世界模式未定；方向需改变隐喻、空间、行动或叙事时刻。
- **Composition Variants**：概念已定，仅改变景别、主体位置、路径、留白或人与环境比例。

首轮优先验证：Scene Motif、空间关系、Character Lock、冒险强度、载体焦点和像素语言。之后再修小道具、材质和局部瑕疵。

## 结果检查

第一眼检查主体、焦点、用途、尺度和 Pixel Adventure Director 整体感；第二眼检查核心状态、世界规则、人物行动和辅助细节；放大检查身份、手脸、物件、建筑、重复噪点、像素尺度和发光。

## Edit or Regenerate

局部编辑适合小范围物件、颜色、身份特征恢复、安全区清理和技术瑕疵。指令必须明确保留项、修改项、范围和禁止变化。

重生成适合母题失效、焦点错误、人与环境关系失效、世界模式/冒险方向错误、构图不适用、角色整体重设计或视觉语言根本不一致。不要用大量局部编辑挽救错误结构。

修改简报：

```text
保留：已成立的角色、色彩、远景或母题
修改：具体位置、比例、行动或关系
删除：无关 UI、符号或装饰
不要改变：Character Lock、留白和已确认约束
```

## 失败重试

同一指令不做无诊断重试。判断是明确要求未被遵循、提示冲突、构图过载、角色身份漂移、像素语言不稳，还是母题本身无感。连续出现同一结构问题时停止随机生成，改变设计或指令策略。

## 系列生成

建立最小连续性包：Character Design Sheet、Character Lock、World Rule、Pixel Density、Palette System、Lighting Logic、Recurring Locations、Fixed Symbols、Narrative Sequence 和 Allowed Changes。同一人物第二次进入新场景前必须先有设定板；每张图单独定义事件、行动、新信息及与前一张的连接。

## 载体提示

- H5：确认全屏开屏、内容卡片或自定义开发容器；记录手机比例、标题按钮安全区、首屏焦点和可延展背景。
- Poster：标题区、远距识别、单一隐喻、避免普通游戏截图。
- Social：平台比例、裁切安全、缩略图、集中主体。
- Icon：单一符号、简单轮廓、极低细节、小尺寸验证。
- Concept Art：世界规则、空间规模、环境功能、角色尺度和探索方向。

## 交付

用户只要图像时先展示结果并简述关键决定，不默认附完整提示词。用户要提示词时提供整理后的可复用指令并区分核心约束与可调变量。用户要修改时先确认真正要改变与保留的部分，再执行。

避免把全部设计文档塞进提示词、堆风格词、不分参考职责、反复同义词、同轮验证过多方向、盲目重试、过长负面清单、结构错误无限局部编辑，以及用户要图却只返回提示词。
